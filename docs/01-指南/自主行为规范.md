# 自主行为规范：目录地盘、下载纪律与自我升级

> 目的：GQY 在主人电脑上自主活动（下载、安装、写文件、自升级）时的硬边界。
> 背景：曾发生 NapCat（724MB）被下载进项目源码目录、launchd 指向项目路径的事故。

## 〇、代码级护栏（硬约束，比提示词可靠）

提示词是软约束，真正的防线在代码里（`src/tools/path_guard.rs`）：

- **写文件工具**（`write_file` / `edit_string` / `apply_patch`）落盘前检查目标路径；
- 目标位于项目源码目录（默认 `~/Desktop/GQY`）内且未放行时**直接拒绝**，报错提示临时文件应放 `~/gqy-workspace`；
- 环境变量（按需设置）：
  - `GQY_PROJECT_DIR`：项目源码目录（默认 `~/Desktop/GQY`）
  - `GQY_WORKSPACE`：她的临时工作区（默认 `~/gqy-workspace`）
  - `GQY_ALLOW_PROJECT_WRITES=1`：开发模式，放行项目写入（主人开发 GQY 时用）

## 一、目录地图（macOS）

| 路径 | 类型 | 用途 | 规则 |
|---|---|---|---|
| `~/Desktop/GQY` | 源码 | GQY 项目仓库 | **只读**。非开发任务不得写入；未跟踪文件一律放别处 |
| `~/Downloads` | **临时** | 下载中转站 | 下载先到这里；解压/安装后清理压缩包 |
| `~/napcat` | **长期** | NapCat 运行目录（QQ 机器人） | 部署目标；日志 `bridge.log` 在这里 |
| `~/qq-napcat` | **长期** | NapCat 专用 QQ 客户端 | 部署目标，不动 |
| `/Applications` | **长期** | 已安装 App | 安装目标；改动需先征得同意 |
| `~/Library/Application Support/gqy` | **长期** | GQY 数据（GQY_HOME） | 记忆/知识库/配置/备份，自动管理 |
| `~/Library/Caches` | **临时** | 系统与 App 缓存 | 可清理 |
| `~/Library/LaunchAgents` | **系统** | 自启项 | **先征得同意**再写 |

## 二、下载与安装纪律

1. **临时区中转**：所有下载先落 `~/Downloads`（或明确的临时目录），确认来源可信后再部署到长期区。
2. **部署即清理**：解压/安装完成后删除压缩包与临时文件。
3. **不进源码目录**：`~/Desktop/GQY` 里出现任何未跟踪的下载物都是违规（`.gitignore` 已加 `/napcat/`、`/qq-napcat/` 兜底）。
4. **来源确认**：GitHub Release / 官网 / 官方脚本才安装；来路不明的不装。

## 三、系统级改动审批

以下操作必须先向主人说明并征得同意：

- 写入 `~/Library/LaunchAgents`、`/Library/LaunchDaemons`
- 安装/卸载 `/Applications` 里的 App
- `sudo` 命令
- 修改系统设置（`defaults write`、`systemsetup` 等）
- 替换正在运行的二进制

## 四、自我升级（正式渠道）

GQY 只能通过以下方式升级自己：

```zsh
# Homebrew 安装版（推荐）
brew upgrade gqy          # CLI
brew upgrade --cask gqy   # 菜单栏 App

# 源码构建版（开发用）
cd ~/Desktop/GQY && cargo build --release --offline
```

**禁止**：手工覆盖 `/opt/homebrew/bin/gqy`、覆盖 `.app` 内嵌二进制、绕过 brew 直接替换文件。

### 升级为什么安全

- 数据全部在 `~/Library/Application Support/gqy`（用户目录），brew 只替换 `/opt/homebrew/Cellar` 里的二进制；
- 升级前后 `conversation.db`、`data/`、`backup/` 分毫不动；
- 路径固定（小写 `gqy`），升级不换目录 = 数据不丢。

## 五、发布流程（给主人的）

1. bump `Cargo.toml` 版本（菜单栏 Info.plist 由 `build.sh` 自动跟随）
2. `git tag vX.Y.Z && git push origin vX.Y.Z`
3. `cargo build --release --offline && zsh macos/GQYMenuBar/build.sh && zsh macos/GQYMenuBar/make-dmg.sh`
4. 上传 `GQY-X.Y.Z.dmg` 到 GitHub Release
5. 更新 `Formula/gqy.rb`、`Casks/gqy.rb` 的 sha256（主仓库 + homebrew-gqy tap 仓库）
6. 用户 `brew upgrade gqy`

## 六、检查清单（GQY 自查）

- [ ] 我刚下载的东西在临时区吗？压缩包清理了吗？
- [ ] `~/Desktop/GQY` 里有没有我留下的未跟踪文件？
- [ ] 我改系统配置前征得同意了吗？
- [ ] 我的日志写在对应目录（如 `~/napcat/bridge.log`）而不是项目里吗？
